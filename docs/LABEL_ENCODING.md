# TrOCR 标签编码修复与升级说明

## 修复的问题

固定通用模型的解码起始符为 EOS（token ID 2），生成序列为 `[2, 正文 token, 2]`。旧训练路径调用 RoBERTa tokenizer 的默认特殊符包装，得到 `[0, 正文 token, 2]`，再右移生成解码输入 `[2, 0, 正文 token]`。这使训练输入比实际生成时多出 BOS（token ID 0）。

新辅助函数 `handwriter.label_encoding.encode_target_labels` 关闭自动特殊符和截断，将训练标签统一为正文 token 后追加一个 EOS。解码起始符保持 2；标签有效性检查、长度检查和训练加载共用此函数。现有 128 token 上限包含尾部 EOS。空文本依然由样本校验器排除。

新训练配置、检查点和新快照记录 `text_then_eos_v1` 编码约定，新快照预处理版本为 2。此修复不改变通用模型权重，也不改变已完成模型的识别解码起始方式。

## 升级已有数据与训练

- 更新源码后运行 `python run_app.py`，或使用 `build.ps1` 重新构建便携包。仅更新 GitHub 源码不会改变已经下载的旧 EXE。
- 旧编码、缺失编码字段的未完成训练任务及检查点不能恢复。请从通用模型新建训练任务；错误消息会说明编码不兼容。
- 原稿、作者档案、训练快照及已完成模型可以保留。快照保存原文字和图像，训练加载器按新编码重新生成标签，并重新执行长度等校验。
- 已完成的旧模型可继续用于识别和回退，修复不会自动重新训练或升级它们。候选模型仍须由用户明确启用。

## 验证与实验边界

新增回归测试覆盖真实离线 RoBERTa tokenizer 的特殊符、正文与 EOS、解码移位、空白/Unicode/标点保留，以及旧编码任务和检查点在读取优化器状态前被拒绝。测试使用合成文字和图像，不需要手稿、下载模型或执行微调。

2026-10-27 发布核验：完整测试集 **79 passed in 54.80s**。这是本地执行记录，不是 GitHub Actions 状态。

在仓库根目录运行：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
python -m pytest tests -q --basetemp ./build/test-temp
```

# Joseph Hooker 手稿识别：冻结对照实验

> **实验性结果。** 在 12 个未参与原训练的信件编号中，经过助手视觉筛选的 72 条行图上，微调候选模型的字符错误率（CER）从 55.64% 降至 39.39%。参考文字尚未经过独立人工金标准复核，结论仅适用于这批筛选后的行图。

## 结果

| 指标 | 通用 TrOCR | 微调候选模型 |
| --- | ---: | ---: |
| 字符编辑错误 / 参考字符 | 928 / 1,668 | 657 / 1,668 |
| 字符错误率（CER） | 55.64% | 39.39% |
| 词编辑错误 / 参考词 | 288 / 328 | 207 / 328 |
| 词错误率（WER） | 87.80% | 63.11% |
| 完全匹配参考的行 | 0 / 72 | 4 / 72 |

CER 下降 **16.25 个百分点**，相对下降 **29.20%**。72 行中，52 行的字符错误减少，10 行持平，10 行增加。以 12 个信件编号为簇进行成对 Bootstrap 重采样（20,000 次，随机种子 20261028），CER 降低量的 95% 百分位区间为 **11.12–22.05 个百分点**。这个区间反映抽样变化，不包含参考文字可能有误的影响。

统计输入按页列于 [metrics.json](metrics.json)。安装 NumPy 后可运行 `python verify_metrics.py`，重新计算总 CER 和上述区间。逐页汇总支持复算统计，但不能独立验证参考文字或模型输出。

## 数据与方法

- 来源：[JosephHookerHTR](https://github.com/jschaefer738b/JosephHookerHTR/tree/ece582973283818621e956163f295fcde672786c)，固定提交 `ece582973283818621e956163f295fcde672786c`。仓库提供 JPG 原图和 PAGE XML 转写；其说明称许多转写由项目志愿者制作。
- 初始候选为 20 页、427 条 XML 行标注；经助手辅助视觉检查后，203 条进入训练快照，其中 120 条用于训练、41 条用于验证，另有 42 条旧测试行。修正后的候选模型根据验证集选取最佳检查点；本次新信件对照未使用上述旧测试行训练或选择模型。
- 新信件按事先固定的哈希排序规则，从排除原 20 页信件编号后的候选中抽取 12 个不同编号，每个编号取一页；所选页面未替换。按源文件、Transkribus 文档标识及图像检查，新材料与原 20 页无重叠。
- 12 页共有 221 条源行。在生成任何本次模型预测前，助手查看原图、裁图与 XML 参考文字，纳入 72 条、排除 149 条；排除原因包括不确定文字、裁图截断和邻行混入。两处明确文字更正在预测前记录，原 XML 不变。此过程是 **AI 辅助检查，不是独立人工金标准**。
- `40_001` 的 XML 行框坐标与原图尺寸不一致；预测前依据原图和 XML 基线进行 0.6 倍坐标恢复，并重新检查该页全部 25 条裁图。原 XML 未被修改。
- 两模型使用相同的已筛选行图、参考文字、图像处理器和生成参数（beam size 3、最多 128 个新 token、无采样）。候选模型为固定的第 19 轮 LoRA 检查点与通用模型的 FP32 合并版本。预测文本首尾空白按应用逻辑去除；字符比较保留大小写、内部空格和标点，WER 按空白分词。
- 模型、抽样规则、参考文字和行图在推断前本地封存；本次对照不进行训练、调参或自动启用模型。统计结果另由 AI 助手独立复算，非独立人工验收。

## 解释与限制

此结果支持“修正版在所筛选的新信件行图上优于通用模型”，不能推广到全部 221 条源行、其他作者或其他材料。测试未衡量自动切行、整页识别、人工校对时间，不能证明这些环节已改善。仓库介绍的是 Hooker 书信资料，未逐页证明均为他本人亲笔。

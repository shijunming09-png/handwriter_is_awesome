# 墨迹 Handwriter 2.0 · 个人英文笔迹训练版

Windows 本地桌面应用，支持英文手写扫描 PDF 自动切行、TrOCR 识别、逐行校对、Word/TXT 导出，并可使用同一作者的人工确认结果训练个人模型。

## 开始使用

1. 将整个 `Handwriter-Personal` 文件夹放在可以写入的位置，双击 `Handwriter.exe`。
2. 交付包已包含通用模型，识别和训练均可离线进行；没有按页费用，也不会上传文稿。
3. 导入 PDF，点击“开始 / 继续识别”，对照原稿修改文字，导出 Word 或 UTF-8 TXT。
4. 保留完整便携文件夹。基础运行库与通用模型约 6.5 GiB，无需安装 Python 或 CUDA Toolkit；GPU 需要可用的 NVIDIA 驱动。

## 建立训练数据

1. 打开“个人笔迹训练”，保存一位作者的名称，将当前任务明确归入该作者。只有关联的任务才会被收集。
2. 在主界面逐行检查文字和完整行框，勾选“已逐字校对，可用于训练”。原识别已经正确、没有改字的行同样可以确认。
3. 检查完整页面后可以使用“确认本页全部文字”。无法辨认或不确定的行标记为“不用于训练”，不要把猜测当作标准答案。
4. 修改文字、行框、拆分/合并或旋转页面会使相关确认失效，需要重新检查。重新识别保留人工校对文字，模型不会自动把自己的输出当作正确标签。
5. 点击训练页面中的数据刷新，查看合格行数、页数、分组和排除原因。

第一版的实验门槛为 **至少 150 个有效确认行、5 个原稿页**，其中训练/验证/测试分别至少 90/20/20 行。它用于开始实验，不代表达到这个数量就一定改善。重复行图会去重，同图对应冲突文字会全部排除，空白、换行混合或超过 128 token 的行不能直接训练；长行可左右拆开后重新确认。

数据按完整页面约 60%/20%/20% 划分。首次正式训练固定保留验证/测试页面，此后新增页面进入训练组，避免同一页面或重复裁图同时参与训练和测评。

## 手动训练与启用

1. 数据达到门槛后，建立训练快照，再手动开始训练。每次快照保存对应行图、确认文字和来源校验值。
2. 训练在独立进程中运行，主窗口仍能响应。训练期间识别互斥；可查看阶段、轮次、损失、错误率和显存占用。
3. 需要暂停时点击取消，程序会保留完整的安全检查点。在训练历史中选择未完成任务，可恢复相同快照、相同标签编码版本的训练。
4. 完成后先查看通用模型与候选模型在相同保留集上的 CER/WER 和逐行差异，再到模型版本页明确启用。新模型不会自动替换当前模型。
5. 可随时回到通用模型。模型切换影响后续识别或明确执行的重新识别，不覆盖已有人工校对。

训练采用冻结 TrOCR 基座、decoder 注意力 LoRA 的方式，不需要 WSL、Docker 或 eScriptorium 服务。软件借鉴其“校对—训练—评估”流程，并不把 Kraken 模型直接当作 TrOCR 模型加载。

源码现已包含标签编码修复：训练目标为正文 token + EOS，旧编码检查点不能继续恢复。升级后请从通用模型新建训练任务；原稿、快照和已完成模型可以保留，旧模型不会自动升级。使用旧便携包时，需要根据修复后的源码重新构建才能应用修复。详见 [升级说明](LABEL_ENCODING.md)。

训练需要 NVIDIA GPU；当前 RTX 5060 8 GB 已进行真实反向传播与模型保存/重载验证。显卡不可用时仍可使用 CPU 识别。数据和模型适配情况会影响训练资源与结果，不承诺固定耗时或准确率。

## 版本、磁盘和任务

- 通用模型保存在 EXE 同目录的 `models`；任务在 `projects`，作者、快照、训练历史和个人模型在 `writers`，日志在 `logs`。
- 保留小型 LoRA 权重和安全检查点以便恢复；每个正式合并模型另需约 1.3 GB。训练开始前至少预留 4 GiB，并查看发布空间提示。
- 通用模型和历史版本不会被自动覆盖或清理。比较不同版本时，应看同一快照的通用/个人模型对比，不能将不同测试集的数字直接排名。
- 新版可读取旧任务，默认使用通用模型且没有训练确认。首次升级保存前保留原始 `project.v1.backup.json`。升级后的任务应使用新版继续编辑。
- 如移动应用或任务，请保留完整目录。外部任务移动后可重新打开并归入作者，以更新记录中的位置。

## 效果与限制

最初交付验证针对功能、真实训练计算和模型载入流程。后续 [Joseph Hooker 书信实验](experiments/joseph-hooker-2026-10/README.md) 在筛选行图上观察到改善，但参考文字尚未独立人工复核，不能推广到整页识别或其他作者。获得真实校对数据后，必须以未参与训练的页面评估；训练可能没有改善，甚至退步，候选模型不会因此自动启用。

主要支持单栏、基本水平的英文手写扫描稿。复杂多栏、密集边注、表格还原、数学公式专用识别、多作者档案、Word/TXT 校对回导、Kraken/eScriptorium 模型兼容及可搜索 PDF 不在本版范围内。

## 排错

- 数据不足或被排除：查看具体原因；确认当前任务已关联作者、行图有效且文字确已校对。
- 训练取消或失败：原模型保持可用，有完整且标签编码版本一致的检查点时可恢复。旧编码检查点需从通用模型新建训练任务。磁盘或显存不足需释放资源后重试。
- 模型文件缺失或校验失败：在模型列表中重新选择通用模型，保留旧任务和训练目录以便排错。
- QtCore 启动问题：便携包已排除其它工具目录中与 Windows 原生 ICU/UCRT 冲突的 DLL，不需要更改系统组件。
- 日志保存在本机。向他人提供日志前可检查其中的本地路径；无需上传原稿排除一般安装问题。

## 开发与重建

使用 Python 3.12。在 PowerShell 中进入源码目录执行 `./build.ps1`，建立锁定依赖并生成 `dist/Handwriter-Personal/Handwriter.exe`。脚本会清理构建 DLL 搜索路径，并运行 `tools/fix_windows_bundle.py`。

源码运行：`python run_app.py`。测试：`python -m pytest tests -q --basetemp ./build/test-temp`。训练子进程由同一程序的 `--training-worker` 入口启动，日志和结果通过本地 JSONL/JSON 传递。

应用源代码保存在便携包 `_internal/handwriter/`。第三方许可见 `THIRD_PARTY_NOTICES.md` 和 `licenses`。公开 IAM 样本仅在本地验证中使用，不随交付包分发。
